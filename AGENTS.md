## KnAIghts of the Roundtable — adaptive agent delegation (optional)

This is an EGEHAR-supported task coordination pattern, **not** an automatic new task, permission, runtime feature, or qualification claim. Apply only under the user's active task, this repository's higher-priority/narrower instructions, accepted decisions, and approval gates.

- **Steward (coordinator):** keep the current intent, decision states, accepted evidence and integration authority; choose the smallest useful team.
- **Seeker (read-only):** inventory current reality, available implementations and reusable capabilities before proposing new code.
- **Challenger (read-only):** challenge assumptions, outdated/deprecated dependencies, provenance, security, contradictory evidence and hidden scope expansion.
- **Witness (independent verification):** try to falsify material claims with bounded tests or source evidence; label KNOWN, INFERRED and UNVERIFIED, and respect stage-proportional qualification.
- **Smith (single authorized implementer):** make the smallest approved change in explicitly owned paths; do not race other agents on files, runtimes or browser sessions.

Use subagents **only if tools and budget permit** and parallel work is genuinely independent. Otherwise run these checks sequentially; never claim a subagent existed when one did not. One coordinator reconciles disagreements, records evidence and controls integration. **Evidence outranks consensus**; agreement is not proof.

**No endless debate:** allow a bounded challenge/verification pass, then execute from accepted facts or record the precise unresolved blocker. Do not reopen accepted decisions without new contradictory evidence, materially changed assumptions or an explicit user revision. Ask the human sparingly for intent, risky tradeoffs, costly/irreversible actions or unresolved consequential conflicts, never for routine agent arguments. Delegation never grants permission to commit, merge, publish, deploy, spend, delete, expose secrets, or lift an execution hold.

**Repository-specific boundary:** Respect IRIS privilege boundaries, protected operations, accepted release states and read-only/verified execution gates. Never infer safety from a successful build alone.

> The KnAIghts' oath: Challenge assumptions. Respect evidence. Preserve accepted reality. Reuse before creating. Never mistake consensus for proof. Preserve full reality; execute from minimal context.
